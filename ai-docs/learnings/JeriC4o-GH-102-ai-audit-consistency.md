### 2026-10-09 — documentation — a sentence stating a general rule did the thing it forbade, three times in one branch
**What happened:** Three separate edits of mine on this branch and its predecessor instantiated the very defect they described. (1) A parenthesis explaining why the reference gate had never caught a malformed section reference quoted that reference form, and `check-references.sh` refused my own fix on the line written to document the defect. (2) A sentence whose entire job was to stop the next editor missing a sync-group member called the Step 2.3 letter table "the third member" when `docs/propagation.md:38` lists it FIRST, and never named the third member at all. (3) A sentence declaring an emission set CLOSED — "an outcome some rule mandates while the set omits it is a defect in this list" — met that condition itself, because the exhaustiveness clause two paragraphs below mandates a taxonomy-gap finding that none of the six values can carry. Every one passed my own reading; every one was caught by a fresh reviewer. None was mechanically detectable: the 32-member structural suite was green at each step, which is consistent with `docs/propagation.md`'s own claim that drift between a list and the prose beside it is invisible to link and syntax checks.
**Rule:** When a sentence states a rule ABOUT a form, a count, an ordinal or a set, the sentence is itself an instance to be checked against that rule — and it is the instance least likely to be checked, because authoring it feels like describing the rule rather than obeying it. Three concrete habits, one per shape observed: describe a forbidden form rather than writing it, or quote a near-miss that cannot match; take an ordinal or a membership claim from the source table in the same breath as writing it, never from memory of having just read it; and after declaring a set closed, enumerate the outcomes every nearby rule mandates and check each has a value. Where the rule is about the document it lives in, the author is structurally the worst reader of it: budget a fresh pass rather than a careful re-read.
**Kind:** correction
**Escalated?** no

**What happened:** Fixing a threshold conflict inside `/ai-audit`, I corrected the detail body in `skills/ai-audit/reference.md` and left the Step 2.3 letter table in `SKILL.md` carrying the old figure — although `docs/propagation.md:38` names those two, plus the footer letter range, as one sync group. The two instances differ in one way worth keeping: there the second copy was inside the same file, here it was a declared sync-group sibling with a table naming it.
**Rule:** Before closing an edit to an instruction file, look the file up in the Propagation Rule table rather than recalling whether it has a group — and treat "I fixed the authoritative copy" as the beginning of the obligation, not the end of it. The sweep has to be run over the GROUP, not over the sentence: a change that removes a duplicate is exactly the shape that feels finished after one file, because the whole point of the change was that the second copy should not exist. Also leave the group named in the text, so the next editor of either member is told the others exist — that converts a one-time sweep into a standing tripwire, and it is what finally caught this.
